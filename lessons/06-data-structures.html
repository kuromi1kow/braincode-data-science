С чего начать

Структура данных определяет способ хранения и доступа. Выберем подходящий контейнер для заказов, настроек и уникальных клиентов.

Почему одна коллекция не подходит для всех вопросов

В журнале посещений повторный визит — отдельное событие. Список хранит порядок и повторы. Преобразовав его в множество, можно узнать число разных посетителей, но восстановить число визитов каждого по одному множеству уже нельзя.

Задайте следующий вопрос: сколько раз пришёл каждый? Здесь удобно сделать имя ключом словаря и увеличивать хранящийся под ним счётчик. А пару координат, которая в рамках задачи не меняется, удобно записать кортежем. Выбор структуры зависит от действий, которые предстоят дальше.

list
Упорядоченная изменяемая последовательность.
dict
Соответствие между ключами и значениями.
set
Коллекция уникальных элементов без позиционных индексов.

Перевод для курса

Словарь как адресная книга

Словарь похож на адресную книгу: зная имя человека, можно найти его адрес или другие контактные сведения. Иначе говоря, мы связываем ключи (имена) со значениями (сведениями). Ключ должен быть уникальным, иначе по одному и тому же имени невозможно определить, чьи сведения нужны. Пары ключей и значений записывают как d = {key1: value1, key2: value2}. Ключ и значение разделяет двоеточие, отдельные пары разделяют запятыми, вся запись заключена в фигурные скобки.

Оригинал и перевод этого отрывка · Swaroop Chitlur · A Byte of Python · CC BY-SA 4.0

Прочитать английский оригинал

A dictionary is like an address-book where you can find the address or contact details of a person by knowing only his/her name i.e. we associate keys (name) with values (details). Note that the key must be unique just like you cannot find out the correct information if you have two persons with the exact same name.

Pairs of keys and values are specified in a dictionary by using the notation d = {key1 : value1, key2 : value2 }. Notice that the key-value pairs are separated by a colon and the pairs are separated themselves by commas and all this is enclosed in a pair of curly braces.

Как это проверить

В реестре группы два человека могут иметь одинаковое имя. Поэтому удобно взять номер студенческого билета ключом, а имя сохранить как значение. Попробуйте дважды присвоить новое значение одному ключу: число записей останется прежним.

Как сохранить порядок визитов и одновременно посчитать уникальных гостей?

На входе журнал стойки регистрации: A17, B04, A17, A17, C09. У третьей строки своё место во времени, даже если такой человек уже приходил. Список хранит все пять визитов и их порядок. По первому и последнему элементам видно, кто открыл и закрыл журнал. Сортировка копии списка удобна для поиска, но меняет смысл вопроса о последнем визите.

Множество тех же кодов содержит три уникальных значения. Доля уникальных гостей в числе визитов равна 3/5, или 60 %. Если требуется узнать, сколько раз пришёл каждый, заведите словарь. При очередном коде возьмите текущее количество с начальным значением ноль и прибавьте единицу. На выходе A17 получил три визита, B04 и C09 — по одному. Сумма значений словаря снова равна пяти.

Для ежедневного отчёта можно использовать ключ (дата, код). Кортеж из двух строк подходит как ключ словаря и сохраняет обе составляющие. Сначала определите, какая информация понадобится следующему расчёту. Если сразу оставить только множество, восстановить частоты и первоначальный порядок из него уже нельзя.

Как представить данные о маршруте?

Станция публикует расписание учебного автобуса. Одна поездка состоит из последовательности остановок: Парк, Музей, Парк, Школа. Повторная остановка у парка осмысленна: автобус возвращается к нему после музея. Список передаст эту деталь и позволит ответить, где автобус находится по счёту. Если сразу сохранить названия как множество, различить вторую и третью остановки уже не получится.

У каждой остановки есть свои данные. Например, её координаты представлены парой чисел, для которых заранее установлен порядок «широта, долгота». Такую пару удобно хранить кортежем. Название остановки можно использовать как ключ в словаре координат. Тогда список отвечает за порядок маршрута, а словарь позволяет быстро получить сведения по известному имени. Если остановка меняет название или два объекта в городе называются одинаково, понадобится устойчивый идентификатор.

Теперь подумайте о вопросе диспетчера: сколько разных остановок посетил автобус? Для такого подсчёта можно временно превратить список названий в множество и посмотреть его длину. Исходный маршрут при этом останется доступен. Такой подход даёт гибкость: сначала сохраняем факты в форме, где существенные различия различимы, затем извлекаем представление для конкретного вопроса.

Почему правка черновика меняет исходный список?

Допустим, вы планируете список аудиторий для лабораторных работ: сначала 201, затем 305. Чтобы попробовать новый вариант, записываете draft = rooms и заменяете первую аудиторию в draft на 204. При проверке исходного rooms неожиданно видно то же изменение. Причина в самом присваивании: имя draft стало ещё одним способом обратиться к уже существующему списку. Копирования его содержимого в этой строке не происходило.

Если требуется отдельная версия простого списка чисел, можно начать с draft = rooms.copy(). Такая команда создаёт другой внешний список с теми же элементами. Теперь замена первого номера изменит только черновик. Это легко проверить на двух списках из пары чисел, прежде чем редактировать длинное расписание. Добавление новой аудитории в конец копии также сохранит длину исходного списка.

У копии есть важная граница. Представьте расписание в виде списка дней, а каждый день — отдельный список аудиторий. Копирование только внешнего списка перенесёт в него ссылки на те же дни. Добавление аудитории внутрь уже существующего дня затронет обе версии. Для этого представления подойдут копии каждого дневного списка в отдельности. Насколько глубоко копировать, зависит от тех элементов, которые вы намерены менять.

Остановитесь и проверьте себя

Пусть plan = [[1, 2], [3]], а draft = plan.copy(). Что будет с plan, если выполнить draft.append([4]), затем draft[0].append(5)?

Разобрать ответ

Первое добавление касается только внешнего draft. Второе меняет общий список первого дня. В результате plan равен [[1, 2, 5], [3]], а draft равен [[1, 2, 5], [3], [4]].

Кому отправить материалы после двух мастер-классов?

После двух мастер-классов организаторам нужны три списка рассылки. Всем участникам положена запись лекций. Практический сертификат получают те, кто дошёл до обеих встреч. Для пропустивших вторую встречу готовят ссылку на повтор. Поскольку одно письмо должно уходить человеку один раз, в этой задаче удобно хранить идентификаторы участников как множества. Повторное сканирование пропуска у входа тогда не увеличит размер рассылки.

На первой встрече присутствовали A, B, C и D. На второй — C, D и E. Операция объединения с символом | соберёт всех, кто присутствовал хотя бы раз: получатся A, B, C, D и E. Пересечение с символом & оставит общих участников C и D. Разность первого множества и второго с символом - даст A и B. Если поменять множества местами, в разности останется только E. Последняя операция тем самым зависит от направления вопроса.

Сверьте общую численность вручную. Сумма четырёх участников первой группы и трёх второй равна семи, но C и D были учтены по два раза. После вычитания размера пересечения остаётся пять человек. Для алфавитной рассылки можно отдельно отсортировать итоговые идентификаторы: оборотные операции с множествами сами порядок не фиксируют.

Как сохранить порядок ожидания?

В очереди сейчас Алия и Марат, затем приходит Дана. Список сохраняет порядок добавления и позволяет обратиться к человеку по позиции.

Python
queue = ["Алия", "Марат"]
queue.append("Дана")
print(queue[0])
print(len(queue))
Показать вывод и объяснение
Алия
3

Метод append добавляет один элемент в конец существующего списка. Индекс 0 обозначает первую позицию, а len считает все элементы. Поэтому первым по-прежнему остаётся прежний посетитель, хотя очередь стала длиннее.

Как посчитать заказы по городу?

Журнал содержит названия городов по одному на заказ. Для каждого города нужен свой счётчик, поэтому используем словарь, в котором ключом станет название города.

Python
counts = {}
for city in ["Актау", "Тараз", "Актау"]:
    counts[city] = counts.get(city, 0) + 1
print(counts["Актау"], counts["Тараз"])
Показать вывод и объяснение
2 1

Пустые фигурные скобки создают словарь. Вызов get возвращает прежнее значение по ключу или начальный ноль, когда город встречается впервые. После прибавления единицы записываем счётчик под тем же ключом, поэтому второй заказ из Актау обновляет прежнюю запись.

Сколько клиентов вернулись на следующий день?

История покупок может содержать много записей одного клиента. Для подсчёта людей оставим по одному идентификатору на день и выделим общих клиентов двух дней.

Python
monday = set(["A", "A", "B", "C"])
tuesday = {"B", "C", "D"}
returned = monday & tuesday
print(len(returned))
print(sorted(returned))
Показать вывод и объяснение
2
['B', 'C']

Множество set сохраняет уникальные элементы, так что два появления A дают одного человека. Операция & берёт пересечение, то есть идентификаторы, встречающиеся в обоих множествах. Порядок множества не задан, поэтому sorted выводит имена в устойчивом порядке для сверки.

Лаборатория · Сколько книг доступно в каждом филиале?

Библиотеки передают повторные сообщения об остатке одного учебника. Каждая строка заменяет предыдущее состояние того же филиала. Сформируйте текущую сводку и поясните читателю разницу между нулём на полке и отсутствием сведений.

Исходные данные

Сообщения расположены от старых к новым. Для отчёта нужны филиалы Юг, Центр, Север и Парк. Каждая запись содержит название филиала и целое неотрицательное число доступных экземпляров.

Запустить лабораторию в Colab

Шаг 1. Сколько раз обновили сведения и сколько филиалов отчитались?

Python
updates = [("Юг", 3), ("Центр", 2), ("Юг", 1),
           ("Север", 0), ("Центр", 4)]
branches = set()
for name, count in updates:
    branches.add(name)
print(len(updates), len(branches))
Проверить результат
5 3

Список хранит пять сообщений в порядке поступления. В каждой итерации пара распаковывается в название и количество. Множество собирает разные названия, поэтому повторные сообщения оставляют в нём всего три филиала.

Шаг 2. Как выбрать для каждого филиала самый свежий остаток?

Python
latest = {}
for name, count in updates:
    latest[name] = count
print(latest["Юг"], latest["Центр"], latest["Север"])
Проверить результат
1 4 0

Словарь связывает один ключ с одним значением. Поскольку список упорядочен по времени, присваивание тому же ключу заменяет старые сведения свежими. Для Юга число 3 заменилось на 1, а для Центра 2 заменилось на 4.

Шаг 3. Как показать отсутствие сведений отдельным сообщением?

Python
required = ["Юг", "Центр", "Север", "Парк"]
for name in required:
    if name in latest:
        print(name, latest[name])
    else:
        print(name, "нет сведений")
Проверить результат
Юг 1
Центр 4
Север 0
Парк нет сведений

Условие name in latest проверяет присутствие ключа в словаре. Ключ «Север» существует, поэтому число ноль попадает в отчёт. «Парк» отсутствует, и отдельная ветка сообщает об этом без догадки об остатке.

Программа выполняется. Где ошибка в выводе?

Python
for name in ["Север", "Парк"]:
    if latest.get(name):
        print(name, latest[name])
    else:
        print(name, "нет сведений")
Разобрать ошибку
Север нет сведений
Парк нет сведений

В условии ноль превращается в ложь, и отсутствующий ключ через get даёт None, который тоже ложен. Поэтому эти разные ситуации получили одинаковую подпись. В данном отчёте правильный вопрос — есть ли ключ в словаре; после проверки можно выводить любое значение, включая ноль.

Самопроверка

Как создать пустое множество?

set().

Гарантирует ли set порядок элементов?
