С чего начать

Класс объединяет состояние и действия объекта. Это удобно, когда у нескольких объектов одинаковое поведение и независимые данные.

Как понять, кому принадлежит состояние

Составьте две карточки студентов на бумаге. На первой напишите имя и положите рядом пустой лист для оценок. Проделайте то же со второй карточкой. Добавление оценки в первый лист не должно менять второй. Именно это поведение мы хотим от двух объектов класса Student.

При создании каждого экземпляра Python вызывает __init__. Запись self.scores = [] внутри этого метода создаёт для каждого студента новый список. Вызов first.add_score(80) сообщает методу, с каким объектом работать. После вызова прочитайте состояния обоих студентов и убедитесь, что менялось нужное.

Что принадлежит классу, а что объекту

Классы и объекты — два основных понятия объектно-ориентированного программирования. Класс создаёт новый тип, а объекты являются экземплярами этого класса. Например, переменная с целым числом ссылается на экземпляр класса int. Объект может хранить данные в переменных, которые ему принадлежат. Переменные объекта или класса называют полями. Объекты также получают поведение через функции, принадлежащие классу. Такие функции называют методами. Эти слова позволяют различать самостоятельные функции и переменные и те, что относятся к классу или объекту. Поля и методы вместе называют атрибутами класса.

Прочитать английский оригинал

Classes and objects are the two main aspects of object oriented programming. A class creates a new type where objects are instances of the class. An analogy is that you can have variables of type int which translates to saying that variables that store integers are variables which are instances (objects) of the int class.

Objects can store data using ordinary variables that belong to the object. Variables that belong to an object or class are referred to as fields. Objects can also have functionality by using functions that belong to a class. Such functions are called methods of the class. This terminology is important because it helps us to differentiate between functions and variables which are independent and those which belong to a class or object. Collectively, the fields and methods can be referred to as the attributes of that class.

Два прибора и три имени в программе

Как метод сохраняет допустимое состояние

В учебной мастерской есть класс Reel для катушки кабеля. Объект хранит остаток в целых метрах. Перед выдачей мастер вызывает метод cut(length). Договоримся о правилах мастерской. Запрошенная длина положительна и не превышает остаток. Успешный вызов уменьшает остаток ровно на запрошенную длину. При нарушении правила метод сообщает об ошибке через ValueError, а остаток сохраняется. Здесь мы рассматриваем запросы, которые уже преобразованы в целые числа.

На катушке десять метров. Отрезаем четыре, остаётся шесть. Следом просят восемь. Если метод сразу выполнит self.remaining -= length, значение на мгновение станет отрицательным. Одного последующего сообщения об ошибке недостаточно, потому что вычитание уже произошло. Надёжнее прочитать текущий остаток, проверить обе границы и выполнить присваивание только после успешных проверок. Возможность выдать все шесть метров проверяйте отдельно. Граница допустима, после операции на катушке останется ноль.

Сформулируйте правило, которое истинно после любого завершённого запроса. Здесь это «остаток всегда целый и не меньше нуля». Такое правило называют инвариантом. Та же идея помогает описать электронный кошелёк, свободные места в аудитории и запас товара. Для каждой модели отдельно выясните, какие действия разрешены при точном равенстве и что увидит вызывающая программа при отказе.

Как объединить имя участника и его данные?

Представим, что в учебной системе есть карточки студентов. Для начала карточке достаточно одного имени. Опишем общий способ создания карточек через класс.

Python
class Student:
    def __init__(self, name):
        self.name = name

first = Student("Алия")
print(first.name)
Показать вывод и объяснение
Алия

Вызов Student создаёт экземпляр класса и передаёт имя методу __init__ для начальной настройки. Параметр self внутри метода указывает на создаваемый объект. Присваивание self.name сохраняет значение в объекте, поэтому его можно прочитать после завершения метода.

Откуда метод берёт прошлое значение?

Посчитаем посещения одного участника. Храним текущее число внутри объекта и вызываем метод один раз на каждое посещение.

Python
class Visits:
    def __init__(self):
        self.count = 0
    def mark(self):
        self.count += 1

record = Visits()
record.mark()
record.mark()
print(record.count)
Показать вывод и объяснение
2

Метод __init__ устанавливает ноль при создании экземпляра. При вызове record.mark() Python передаёт этот же экземпляр в параметр self, а += 1 увеличивает его счётчик. Ко второму вызову первый результат сохраняется, поэтому получаем два.

Могут ли две группы хранить разные списки?

Пусть один студент записался в утреннюю группу, а вечерняя ещё пуста. У каждой группы должен быть собственный список записей, иначе изменения случайно смешаются.

Python
class Group:
    def __init__(self):
        self.names = []
    def enroll(self, name):
        self.names.append(name)

morning = Group()
evening = Group()
morning.enroll("Дана")
print(morning.names, evening.names)
Показать вывод и объяснение
['Дана'] []

Выражение [] выполняется заново при каждом вызове __init__, создавая отдельный список. Метод enroll изменяет список того экземпляра, через который его вызвали. Пустой вывод для evening служит короткой проверкой независимости двух групп.

Лаборатория · Сколько образцов выдержали проверку?

Две лаборатории испытывают упаковку на герметичность. Один объект будет хранить итоги нескольких проверок одной партии. Задача программы — принимать протоколы, отклонять невозможные записи и выдавать проверяемый итог по партии.

Исходные данные

Партия K-17 получает сначала протокол «5 проверено, 1 протекает», затем «3 проверено, 2 протекают». У партии L-02 отдельный протокол «4 проверено, 0 протекает». Все числа в протоколах целые. Запись допустима, когда проверено хотя бы одно изделие, а число протечек находится между нулём и количеством проверенных включительно.

Шаг 1. Как записать первую проверку так, чтобы показатели двух партий хранились независимо?

Python
class Batch:
    def __init__(self, label):
        self.label = label
        self.tested = 0
        self.leaks = 0

    def record(self, tested, leaks):
        if tested <= 0 or leaks < 0 or leaks > tested:
            raise ValueError("невозможный протокол")
        self.tested += tested
        self.leaks += leaks

    def passed(self):
        return self.tested - self.leaks

first = Batch("K-17")
second = Batch("L-02")
first.record(5, 1)
print(first.label, first.tested, first.leaks)
print(second.label, second.tested, second.leaks)
Проверить результат
K-17 5 1
L-02 0 0

Метод record увеличивает счётчики только того экземпляра, у которого его вызвали. В первой партии уже испытали пять упаковок. У второй партии ещё нет результатов, поэтому оба её счётчика по-прежнему равны нулю.

class DraftBatch:
    def __init__(self):
        self.tested = 5
        self.leaks = 1

    def record(self, tested, leaks):
        self.tested += tested
        if not 0 <= leaks <= tested:
            return False
        self.leaks += leaks
        return True

print(draft.record(2, 3))
print(draft.tested, draft.leaks)

Объект Cart хранит сумму покупок

Первый экземпляр получает товары на 100 и 250

Второй экземпляр остаётся с total=0

Python
class Cart:
    def __init__(self):
        self.total = 0
    def add(self, price):
        if price < 0:
            raise ValueError("Отрицательная цена")
        self.total += price

a, b = Cart(), Cart()
a.add(100)
a.add(250)
print(a.total, b.total)

self указывает на конкретный экземпляр. total в __init__ относится к одному объекту. Изменяемый список на уровне класса стал бы общим для экземпляров. Для простых расчётов функция часто яснее класса. Scikit-learn также использует объекты с методами fit и predict.

Самопроверка

Для чего нужен self?

Для доступа к состоянию текущего экземпляра.

Когда выполняется __init__?

При создании экземпляра после выделения объекта.

Чем экземпляр отличается от класса?

Экземпляр представляет отдельный объект, класс описывает его тип.

Где легко ошибиться

  • Общий изменяемый атрибут класса случайно связывает экземпляры
  • Метод забывает self и получает неверное число аргументов
  • Класс хранит состояние, которое не нужно задаче: упростить до функции
