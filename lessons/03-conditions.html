Как выбрать одну ветку

Запишите правило словами: при заказе от 5 000 тенге покупателю доступен другой тариф. Слово «от» включает ровно 5 000. Поэтому проверка amount >= 5000 возвращает True на границе. Напишите по примеру с каждой стороны порога до того, как начнёте писать if.

В цепочке if / elif / else Python идёт сверху вниз и выполняет первый подходящий блок. Если большой заказ проходит сразу два порога, более высокий порог проверяют раньше. Четыре пробела слева группируют команды, которые относятся к одной ветке.

Когда программа выбирает действие

До сих пор Python выполнял инструкции последовательно, сверху вниз. А если вы хотите изменить порядок выполнения? Допустим, программа должна принимать решения и по-разному действовать в разных ситуациях: выводить «Доброе утро» или «Добрый вечер» в зависимости от времени суток. Инструкция if проверяет условие. Если оно истинно, выполняется один блок инструкций, блок if. Иначе выполняется другой, блок else. Часть else необязательна.

Оригинал и перевод этого отрывка · Swaroop Chitlur · A Byte of Python · CC BY-SA 4.0

Прочитать английский оригинал

In the programs we have seen till now, there has always been a series of statements faithfully executed by Python in exact top-down order. What if you wanted to change the flow of how it works? For example, you want the program to take some decisions and do different things depending on different situations, such as printing 'Good Morning' or 'Good Evening' depending on the time of the day?

The if statement is used to check a condition: if the condition is true, we run a block of statements (called the if-block), else we process another block of statements (called the else-block). The else clause is optional.

Как это проверить

Нарисуйте две дорожки для условия total >= 5000. Проведите по ним два заказа: ровно 5000 и 4999. Отметьте первую строку, на которой пути расходятся, и первую строку после ветвления, на которой снова встречаются.

Получат ли скидку два покупателя с одной суммой заказа?

Магазин даёт скидку 10 % участникам клуба на покупки от 8000 тенге включительно. Здесь две независимые проверки. Сумма сравнивается с порогом выражением amount >= 8000, участие в клубе хранится как True или False. Общее условие с and истинно лишь при выполнении обеих проверок.

Возьмите заказ ровно на 8000. Участник заплатит 7200 тенге, другой покупатель заплатит все 8000. Теперь оставьте участие включённым и уменьшите сумму до 7999. Скидка исчезнет. В каждой паре опытов вы изменили одно свойство и можете объяснить, почему программа выбрала другую ветку. Если пробовать только крупные заказы участников клуба, ошибку в выборе оператора на границе легко пропустить.

До расчёта скидки предусмотрите случай отрицательной суммы. Отрицательное число может прийти из записи о возврате. Смысл возврата и правила его расчёта отличаются от покупки, поэтому программе стоит сообщить о неподходящих данных. В аналитике тот же приём помогает отдельно учитывать заказы с неизвестным статусом до подсчёта долей.

Как проверить пропуск в лабораторию четырьмя опытами?

Пусть в учебную лабораторию с работающей печью можно войти при двух условиях: дежурный присутствует и у студента есть защитные очки. Обозначим эти факты именами supervisor и glasses. У каждого только два допустимых значения. Прежде чем строить большое условие, перечислите все сочетания и подпишите ожидаемый ответ обычными словами. Для двух логических признаков получится четыре строки. Они образуют таблицу истинности для выражения supervisor and glasses.

Первую проверку многие делают для случая, когда всё в порядке: дежурный рядом, очки надеты, вход разрешён. Вторая очевидная проверка, когда нет ни очков, ни дежурного, тоже полезна. Однако если заменить and на or, программа пройдёт обе эти проверки. Разницу обнаружат только два оставшихся случая. В каждом из них один признак истинный, другой ложный. Именно такие сочетания часто раскрывают неверное прочтение слова «и».

Если вам нужно показать предупреждение при нарушении правил, проверяйте not (supervisor and glasses). Оно истинно, когда не выполнено хотя бы одно требование. Запись not supervisor and not glasses пропустила бы случай студента без очков при дежурном. Проговорите условие для одного конкретного человека, прежде чем заменять выражение на более короткое.

Какие значения взять для проверки промежутка времени?

Читальный зал открывается в 9 часов и закрывается в 18 часов ровно. Чтобы пока обойтись без обработки минут, договоримся, что программа получает целый час от 0 до 23. Посетитель, пришедший ровно в 9, успевает зайти. В 18 зал уже закрыт. Эти две фразы определяют, куда относятся точки на каждой границе. Для такой договорённости подходит сравнение 9 <= hour < 18.

На бумаге начертите линию времени и отметьте соседние целые часы у каждой границы. Для 8 часов ответ «закрыт», для 9 и 10 «открыт». У второй границы зал открыт в 17 часов и закрыт в 18 и 19. Такая подборка полезнее длинной серии примеров, взятых только в середине дня. Если кто-то заменит строгое сравнение справа на нестрогое, первым это обнаружит случай hour = 18.

Значения -1, 24 и дробные часы не входят в нашу договорённость о входных данных. Простое сравнение вернёт False для -1, однако сообщение «зал закрыт» ошибочно подтвердит, будто такой час существует. Если программа получает данные от человека, можно сначала проверить допустимость часа и сообщить о неправильном вводе. Вопрос о расписании имеет смысл только для корректного времени.

Как определить, какая ветка перекрывает другую?

На панели теплицы для датчика влажности нужны три сообщения. При значении ниже 20 процентов срочно вызывают дежурного. От 20 до 39 включительно планируют полив. С 40 показывают «полив пока не нужен». Датчик передаёт целое число от 0 до 100. Перед набором кода запишите три пробных показания: 12, 30 и 54. Каждая ветка должна хотя бы раз выбраться по назначению.

Представьте программу, которая сначала проверяет moisture < 40 и пишет «запланировать полив», а потом в elif проверяет moisture < 20. При влажности 12 первое условие уже истинно. Выполнение цепочки заканчивается на первой ветке, хотя вторая проверка тоже была бы истинной сама по себе. Ни одно допустимое значение не попадёт в такую срочную ветку. В контексте теплицы ошибка серьёзнее, чем просто неправильно подписанный диапазон.

Начните со срочного порога moisture < 20. Ко второй проверке moisture < 40 программа дойдёт только после ложного ответа на первую, поэтому слева уже известно moisture >= 20. Эта информация делает вторую ветку точным интервалом. С помощью else закройте оставшиеся значения. Если вместо elif написать отдельный if, при влажности 12 можно получить два противоречивых сообщения. Сразу решите, допускает ли задача несколько одновременно выполненных действий.

Попадает ли заказ на границу тарифа?

Бесплатная доставка начинается с 5 000 тенге включительно. Перед тем как писать весь тариф, проверим одно сравнение ровно на пороге.

Python
amount = 5000
print(amount >= 5000)
print(amount > 5000)
Показать вывод и объяснение
True
False

Оператор >= включает равное значение, поэтому первое выражение даёт True — истину. Строгий знак > проверяет только превышение, и второе выражение даёт False — ложь. Такое различие легко пропустить, если проверять только заказы на 6 000.

Как программа выбирает одно сообщение?

Посылку можно забрать, если в ячейке осталась хотя бы одна коробка. Подставим ноль и проследим, какая часть программы выполнится.

Python
boxes = 0
if boxes > 0:
    print("Можно забирать")
else:
    print("Ячейка пуста")
Показать вывод и объяснение
Ячейка пуста

Строка if задаёт проверку, а отступ в следующей строке показывает, какое действие зависит от неё. Ноль не больше нуля, поэтому Python сразу переходит к ветке else. Если изменить boxes на 1, будет выбран первый вывод.

Почему важен порядок скидок?

При сумме от 10 000 участник клуба получает скидку 15 процентов. Для остальных заказов от 5 000 действует скидка 5 процентов. Запишем правила в порядке проверки.

Python
amount = 12000
member = True
if member and amount >= 10000:
    discount = 15
elif amount >= 5000:
    discount = 5
else:
    discount = 0
print(discount)
Показать вывод и объяснение
15

Оператор and требует, чтобы одновременно выполнялись оба условия первой строки проверки. Заказ участника на 12 000 подходит, и Python пропускает оставшиеся ветки цепочки. Если поставить более широкий порог 5 000 первым, этот же заказ преждевременно получит только пять процентов.

Лаборатория · Проверить режим учебного датчика на всех порогах

В учебном макете табло показывает один режим в зависимости от числа занятых мест. Реализуйте правило, проверьте вход слева и справа от порога, а затем поймайте ошибку с порядком веток. Вместимость зала — десять мест.

Исходные данные

Датчик возвращает целое число occupied. Отрицательное значение и число больше десяти обозначают ошибку. Если свободных мест три и больше, табло пишет «Можно входить». При одном или двух свободных — «Осталось мало мест». При нуле свободных — «Зал полон».

Шаг 1. Сколько свободных мест и допустимо ли показание 8?

Python
capacity = 10
occupied = 8
free = capacity - occupied
valid = 0 <= occupied <= capacity
print("Свободно:", free)
print("Допустимо:", valid)
Проверить результат
Свободно: 2
Допустимо: True

Правило табло описано через свободные места, а датчик передаёт занятые. Вычитание связывает две величины. Проверка допустимости понадобится до выбора сообщения: даже неверное число можно вычесть из десяти и получить внешне убедительный результат.

Шаг 2. Как выбрать единственное сообщение для этих двух свободных мест?

Python
if not valid:
    message = "Ошибка датчика"
elif free == 0:
    message = "Зал полон"
elif free <= 2:
    message = "Осталось мало мест"
else:
    message = "Можно входить"
print(message)
Проверить результат
Осталось мало мест

Сначала цепочка отводит ошибочные показания в отдельную ветку. До проверки free <= 2 доходят только допустимые положительные остатки, потому что случай free == 0 проверен раньше. Поэтому в третью ветку попадут только одно и два свободных места.

Шаг 3. Как убедиться, что на соседнем значении сообщение действительно поменяется?

Python
occupied = 7
free = capacity - occupied
valid = 0 <= occupied <= capacity
if not valid:
    message = "Ошибка датчика"
elif free == 0:
    message = "Зал полон"
elif free <= 2:
    message = "Осталось мало мест"
else:
    message = "Можно входить"
print(free, message)
Проверить результат
3 Можно входить

После изменения occupied заново вычислите зависимые величины. Прежнее значение free осталось бы равным двум и скрывало бы переход. Соседние показания 7 и 8 проверяют именно границу между двумя сообщениями при неизменной вместимости.
