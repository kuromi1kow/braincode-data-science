Что происходит между файлом и числом

В CSV цена 250 записана символами. Чтение строки ещё не делает её числом. Сначала получите поле с именем price, преобразуйте его и только затем умножайте на количество. Для значения bad преобразование не определено. Запишите номер такой строки, чтобы позже можно было исправить источник.

Для отчёта оговорите политику: корректные строки участвуют в сумме, ошибочные попадают в отдельный список. Отсутствующий файл означает другую проблему: данных для анализа вообще не оказалось. Так можно отличить честный нулевой итог от сорвавшегося чтения.

Как отличить пустую строку от конца файла

Затем откроем тот же файл для чтения. Указывать режим необязательно: по умолчанию текстовый файл открывается для чтения. В цикле будем считывать по одной строке методом readline объекта файла. Метод возвращает строку целиком вместе с символом перевода строки в конце, если он есть. Когда возвращается пустая строка, мы достигли конца файла и выходим из цикла через break. В конце файл закрывается.

Оригинал и перевод этого отрывка · Swaroop Chitlur · A Byte of Python · CC BY-SA 4.0

Прочитать английский оригинал

Next, we open the same file again for reading. We don't need to specify a mode because 'read text file' is the default mode. We read in each line of the file using the readline method in a loop. This method returns a complete line including the newline character at the end of the line. When an empty string is returned, it means that we have reached the end of the file and we 'break' out of the loop.

In the end, we finally close the file.

Как это проверить

Пустая строка внутри текстового файла может состоять из одного символа переноса. В Python её представление — "\n". В конце файла readline возвращает "". Если сначала вызвать strip(), то эти два разных случая совпадут. Для обычного чтения всех строк удобно писать with open(...) as f и for line in f.

Считать ли запятую в названии товара новой колонкой файла?

В CSV сохраняют наименование и цену изделия. Строка с полем в кавычках может содержать название «Чай, зелёный». Простое разбиение текста по каждой запятой превратит одну колонку с названием в две. Используйте csv.DictReader с согласованным разделителем и откройте файл с явно заданной кодировкой. Тогда цена останется привязана к нужной колонке, если поставщик соблюдает формат.

Пусть в четырёх строках колонка price содержит '120', пустую строку, '90' и 'ожидается'. Непустая строка ещё не гарантирует, что перед нами число. Попробуйте преобразовать каждую цену в int. Для двух строк преобразование успешно, сумма известных цен равна 210. Для остальных сохраните номер записи и причину пропуска. Отчёт «210 по двум из четырёх» позволяет оценить полноту результата.

Сведите обработку ValueError к операции преобразования. Если CSV не удалось открыть из-за неверного пути, сообщите об этом отдельно. Пустой отчёт с нулевой суммой иначе будет выглядеть как успешная обработка файла без покупок. При исправлении выгрузки сохраните оригинал и запишите исправленные значения в другой файл.

Одна запись в CSV и JSON

Кружок публикует расписание. Одна встреча называется «Графики, часть 1», проходит в кабинете 204 и занимает 90 минут. Выбирая формат хранения, сначала нарисуйте запись на бумаге. У встречи три именованных поля. Значение названия включает запятую, номер кабинета иногда записывают с буквой, а длительность будет участвовать в арифметике. Эти детали определяют, что и когда следует проверять при чтении.

В CSV удобно хранить последовательность встреч с общим набором столбцов. Заголовок задаёт имена полей. Поле, внутри которого есть запятая, можно заключить в двойные кавычки. При разделителе-запятой корректный CSV-парсер вернёт название одним значением. Ручной split по запятой даст лишний фрагмент. При обычном чтении через csv.DictReader длительность «90» придёт как строка. Для расчёта часов её нужно преобразовать в число.

Если у каждой встречи появится свой список материалов, в JSON его удобно сохранить прямо как массив строк. Поле duration_minutes можно записать числом 90, а room — строкой "204Б". Проверьте тот же пример после записи и повторного чтения. Совпали ли текст названия, тип длительности и число материалов? Почему один файл открывается из блокнота и теряется из терминала

Представьте папку проекта с двумя соседними каталогами, data и notebooks. В data лежит stations.csv, в notebooks лежит упражнение. Относительный путь data/stations.csv отсчитывается от рабочей папки процесса. Если процесс запущен из корня проекта, путь ведёт к нужной таблице. Если рабочая папка уже notebooks, тот же текст заставит программу искать data внутри notebooks. Местоположение файла с кодом и рабочая папка могут различаться.

Первый шаг при FileNotFoundError — вывести Path.cwd() и получившийся полный путь. Сравните его с фактическим расположением файла. Для упражнения можно явно договориться запускать блокнот из корня проекта. В обычном файле программы корень можно вычислить относительно __file__. У ячейки интерактивного блокнота этой переменной обычно нет. Способ вычисления пути должен совпадать со способом запуска, который получит ваш одногруппник.

Когда файл найден, нужно перевести его байты в текст. Если экспорт сделан в UTF-8, откройте его с encoding="utf-8". Проверьте знакомое слово с буквами «Қ» или «Ө»: латинские цифры и запятые могут выглядеть одинаково при нескольких способах декодирования. При ошибке сначала уточните кодировку источника. Пропуск нечитаемых байтов способен превратить два разных названия в одинаковые, и последующая группировка объединит разные станции.

Как учесть каждую строку в отчёте о загрузке

На соревновании волонтёры прислали один столбец с длительностью забега в секундах. В учебном файле четыре строки после заголовка: 60, пустая строка, −3 и 75. Значения указаны целыми секундами, отрицательная длительность запрещена по смыслу. Организатор просит среднее время и список строк, которые ему нужно проверить. В этой задаче корректная обработка ошибок входит в результат исследования.

Обрабатывайте исходные строки вместе с номерами. Сначала проверьте, пуста ли строка после удаления пробелов по краям. При необходимости преобразуйте текст в int и отдельно проверьте знак. Запись «−3» в примере означает обычное отрицательное значение, в текстовом файле оно записано как -3. Преобразование такой строки успешно: причину отказа «отрицательная длительность» создаёт ваше собственное правило. Это отдельный случай от текста, который вообще нельзя превратить в число.

После прохода должны сойтись два счётчика. Две принятые строки плюс две отклонённые дают все четыре исходные строки. Сумма принятых значений равна 135, среднее равно 67,5 секунды. Если в знаменатель ошибочно поставить четыре строки, выйдет 33,75. Вместе с итогом сохраните номера и причины отклонения. Следующий участник сможет повторить расчёт и запросить исправления у волонтёров.

Как читать текст по одной строке?

Для опыта используем StringIO из стандартной библиотеки. Такой поток хранит текст в памяти и даёт потренироваться в чтении без создания файла на диске.

Python
from io import StringIO
with StringIO("Актау\nТараз\n") as source:
    for line in source:
        print(line.strip())
Показать вывод и объяснение
Актау
Тараз

Последовательность символов обратная косая черта и n в строковом литерале обозначает перевод строки. Цикл получает строки по одной, а strip убирает пробельные символы по краям, включая перевод строки. Блок with закроет поток после выхода; для реального файла возможен такой же обход внутри with open(...).

Как отличить плохую запись от числа ноль?

Из текстового файла поступили три цены. Одна запись содержит слово, поэтому перевод в целое число завершится исключением. Посчитаем общую сумму и отдельно число непригодных строк.

Python
from io import StringIO
total = 0
bad = 0
with StringIO("120\nошибка\n0\n") as source:
    for line in source:
        try:
            value = int(line.strip())
        except ValueError:
            bad += 1
            continue
        total += value
print(total, bad)
Показать вывод и объяснение
120 1

Поток StringIO имитирует файл в памяти. Блок try охватывает преобразование строки, а except ValueError обрабатывает случай текста, который нельзя прочитать как целое число. Команда continue пропускает сложение только для плохой строки, поэтому запись 0 остаётся корректной ценой.

Как прочитать CSV с запятой внутри названия?

В CSV название товара иногда само содержит запятую. Хранение текста в памяти через StringIO позволяет проверить разбор одной строки с кавычками, прежде чем использовать настоящий файл.

Python
import csv
from io import StringIO
text = 'item,price\n"Чай, зелёный",450\n'
with StringIO(text) as source:
    for row in csv.DictReader(source):
        print(row["item"])
        print(int(row["price"]) * 2)
Показать вывод и объяснение
Чай, зелёный
900

DictReader использует первую строку как названия полей и распознаёт запятую между кавычками как часть названия товара. Значение цены при чтении остаётся строкой, поэтому перед умножением на количество вызываем int. Для чтения того же формата с диска передайте DictReader файловый объект из open с параметрами encoding="utf-8" и newline="".

Лаборатория · Можно ли сверить остаток по накладным?

Учебный склад начал день с 30 упаковками. В конце дня вам передали CSV из учётной системы. Подготовьте отчёт о движении упаковок и сохраните номер строки, которую придётся уточнить у кладовщика.

Исходные данные

Первая строка содержит имена полей. Разделитель — точка с запятой. Значение qty записано положительным целым числом. Направление задаёт отдельное поле kind со значением «приход» или «выдача». Строку с нарушением этих правил пропустите и укажите причину. Текст файла в упражнении открывается через StringIO.

Шаг 2. Как отделить пригодные операции и оставить след для исправления источника?

Python
events = []
issues = []
for line, row in enumerate(rows, start=2):
    try:
        qty = int(row["qty"])
    except ValueError:
        issues.append((line, "количество не целое"))
        continue
    if qty <= 0 or row["kind"] not in ("приход", "выдача"):
        issues.append((line, "проверьте вид операции и количество"))
        continue
    events.append((row["kind"], qty))
print(events)
print(issues)
Проверить результат

В этой выгрузке каждая запись занимает одну физическую строку. Отсчёт начинается с двух из-за заголовка. До вычислений доходят три операции, а четвёртая строка файла с текстом «два» получает отметку для проверки.

Шаг 3. Как сверить остаток двумя суммами и назвать пределы этого расчёта?

Python
incoming = sum(qty for kind, qty in events if kind == "приход")
outgoing = sum(qty for kind, qty in events if kind == "выдача")
balance = 30 + incoming - outgoing
print("Приход:", incoming, "Выдача:", outgoing)
print("Остаток по принятым строкам:", balance)
print("Принято:", len(events), "Требует проверки:", len(issues))

Практика и домашнее задание

Пример из блокнота

JSON-запись: {"name":"Алия","score":85}

json.dump сохраняет объект, json.load читает его обратно

ensure_ascii=False сохраняет русские символы в читаемом виде

Python
import json
from pathlib import Path
path = Path("student.json")
student = {"name": "Алия", "score": 85}
with path.open("w", encoding="utf-8") as f:
    json.dump(student, f, ensure_ascii=False)
with path.open(encoding="utf-8") as f:
    loaded = json.load(f)
print(loaded)
assert loaded == student

Режим w удаляет прежнее содержимое при открытии. В csv.DictReader все прочитанные значения сначала являются строками. Надо преобразовать цену в число и проверить результат. Нельзя молча ловить все исключения, иначе повреждённые данные выглядят как успешный запуск.
